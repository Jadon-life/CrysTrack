## Authoritative accounting

Candidate **0015_sep28_crystal_shards.sql** is additive, after 0014, and creates:

- Private `crystrack_sep28_crystals` functions, fixed empty `search_path`.
- Owner-readable `sep28_crystal_preferences`, `sep28_crystal_awards`,
  `sep28_crystal_events`, `sep28_crystal_moments`, all with RLS.
- Source transaction triggers and three owner-bound RPCs: state, configure,
  claim-moment. None accepts an owner, shard amount, action kind or source key.

Public tables permit authenticated SELECT only, filtered by owner. Anonymous,
other owners and direct ledger/preferences/moment writers cannot mint/modify
awards. Private functions are not executable by public/anon/authenticated/service
roles. SECURITY DEFINER is limited to source trigger entry points and owner-bound
RPCs; all object references are qualified. No client activity event is proof.

| Persisted source | Award | Deterministic identity / reversal |
| --- | --- | --- |
| Verified durable routine outcome changes to completed | +5 | Durable daily routine ID; undo/skip revokes, recompletion reconciles same identity |
| Verified non-empty all-completed day closes | +50 | Frozen daily record ID; no open-day booking, empty/incomplete/unknown never qualify |
| Owned active goal's canonical saved-zone check-in | +25 | Goal ID + canonical occurrence key; duplicate conflicts, delete/cascade revokes |
| Persisted assignment completion | +30 | Assignment ID; repeat is neutral, undo/delete revokes; late completion also allowed |
| Authenticated genuine spending entry | +5 | Money-entry ID, independent of amount; classification edit/delete reconciles |

Money rows generated by service-role/worker inserts, debt, expected-flow, parent
or bill origins are excluded. Transfers, savings, income, releases and repayments
do not earn. Origin eligibility is captured on insert, so FK clearing cannot turn
an automatically generated row into a manual expense. Reward triggers do not
change any money amount, balance, target, date or financial calculation. Stable
source IDs/owners and goal occurrence identity cannot be changed to mint again.

An owner advisory lock serializes preference changes and award reconciliation.
Each source has at most its rule's fixed net balance. Actual balance changes append
positive or negative immutable ledger deltas, unique per source revision, in the
same transaction as the source write. Failed transactions roll back both. The
summary **sums the event ledger**, not a client cache or mutable total. Independent
reconstruction is `SELECT sum(delta) FROM sep28_crystal_events WHERE user_id=...`;
tests compare this with the reconciled source balances.

No backfill: old money/goal metadata edits and already-completed assignments or
legacy materialized task rows do not create past awards. The ledger registers new
source actions only. The existing sealed closed-day guard remains intact, with no
repair bypass. Open-day evidence invalidation revokes its task points; restoring
evidence alone never grants retroactive points. Closed-day changes are rejected by
Piece 2C, and all-done closure is idempotent. Future privileged correction workflows
require separate review rather than disabling those guards.

## Opt-out and day bonus policy

Rewards default on at first reward-state access or new source action. Off means no
future positive accrual and no reward UI/alerts, while legitimate historical audit
remains. Undo/edit/delete still revokes an action's earned shards while off. Reads,
re-enabling or metadata edits never catch up disabled actions. A genuine fresh
completion after undo may earn again, capped to the same single source balance.

The +50 bonus requires rewards enabled for the **entire saved-zone day**, beginning
the next full day after activation/re-enabling. This deliberately excludes partial
activation days and days crossing an opt-out, including delayed worker recovery.
Only the trusted daily closure transaction can book it. No pending +50 is presented
as earned; open today remains open in the streak and reward UI. Toggling rewards
does not remove already-earned closed-day bonuses.

## Levels and notices

Level 1 starts at zero. The first segment costs 500 shards, then 600, 720, 864,
1037... Each requirement is the previous **integer** requirement multiplied by 6/5,
rounded **up**. Cumulative thresholds are 500 for level 2, 1100 for level 3, 1820 for
level 4, 2684 for level 5. The card distinguishes lifetime net ledger total from
shards into the current segment. SQL uses integer-valued numeric; TypeScript uses
BigInt, including beyond JS safe integers. Percentage conversion is display only,
unrelated to money. Exact stages: Raw 1–2, Shard 3–4, Cluster 5–6, Prism 7–9,
Radiant 10+.

First-reached levels have durable unique moment records. An atomic claim marks
notices delivered **before** display; concurrent/restored tabs and reversal/regain
cannot replay a moment. Delivery is at-most-once: an interrupted tab/network may
consume a notice without displaying it, intentionally preferring quietness over
replaying celebrations. Disabling rewards retires unclaimed notices. Notices do
not steal focus, are skippable by button/Escape, expire after six seconds, and have
no motion effect (including reduced-motion mode). The nav ring and Insights bar
have accessible level/progress text, tabular numbers and 40px controls.

## Related minimum changes

Assignment API/UI had explicitly blocked overdue completion. That block is removed
so +30 is available for real late completions; the original list/status design is
retained with encouraging copy and an accessible completion control. No new late
lifecycle is introduced. Goal GET/check-in now agree on saved scheduling timezone,
matching canonical reward eligibility rather than using location metadata.

The Wealth form retains an optional UUID and timestamp for an expense submission
across a failed-response retry. The expense POST binds that ID to the persisted
owned money row, returns an identical replay without another insert/award, and
rejects changed payloads with 409. Concurrent inserts use the existing unique
money-entry ID. Decimal comparison is textual; no money arithmetic is added.
Savings/transfers keep their existing behavior. Legacy clients that omit the ID
still create a distinct persisted entry on each POST; clients should retain the ID
when retrying one intent. Direct distinct source rows are distinct logs, not
fuzzy-deduplicated by amount/date. Deletion reverses its source award; a genuinely
new persisted row is reconciled by its deterministic identity.

The API helper emits only a crystal **read invalidation** after relevant writes.
It cannot award anything. Requests have generation/abort guards; preference writes
suspend older summary reads and refresh after settlement. Settings changes notify
other tabs to reload. New endpoints are private/no-store, and missing migration/RPC
fails with unavailable UI, never fake totals. A synthetic Preview summary is
explicitly disabled. Its new PUT/POST writers are in the audited inventory and
remain intercepted by the existing deny boundary before real services.
